# Design

## Context

The harness is a template. `.claude/`, `AGENTS.md`, and `HARNESS-SETUP.md` are copied into a target repository (always a git repository) on native Windows, with no OS sandbox. Workflow rules reach the agent through `AGENTS.md`, which is loaded every session, and through skills, which are loaded on demand. The `/opsx:*` command files are generated by OpenSpec and cannot carry harness rules.

Facts from the Claude Code permission docs that shape the guardrails:

- Deny rules block in every mode, including `bypassPermissions`.
- Explicit `ask` rules still prompt in `bypassPermissions`.
- `bypassPermissions` skips the built-in protection of `.claude/` and `.git`.
- Read deny rules cover the file tools and the file commands Claude Code recognizes (`cat`, `head`, redirects). They do not cover a script that opens files itself.
- A `PreToolUse` hook that exits 2 blocks the call before permission rules are evaluated. `onFailure: "block"` makes a hook that fails or times out block the call.

## Goals / Non-Goals

**Goals:**
- The prompts left during Build in `bypassPermissions` mode are `git push` and the built-in prompts no mode can switch off.
- Guardrails fail closed.
- `AGENTS.md` stays at or under 40 lines.

**Non-Goals:**
- Stopping a determined bypass, such as a script that opens `.env` itself. Without an OS sandbox nothing in Claude Code settings can stop it. The README says so, and recommends keeping real secrets out of the working tree.
- Testing in this template repository, which has no git, that the push rules work. They are checked by feeding JSON to the hook directly.

## Decisions

**Explain-back after Build, before review.** The human needs the flow in their head to judge review findings. Asking two questions about the flow (one on a failure path, one on a design decision) is the smallest check that tells real understanding from having read a summary. *Alternatives:*
- Learning output style with `TODO(human)`: rejected, because the human chose not to write code by hand.
- A quiz after archive: rejected, because it comes too late to change anything.

**Small and Large paths, chosen by the human after `/brief`.** Small means one module, and no change to behavior that `openspec/specs/` describes. A Small plan is a single `plans/<name>.md` with three sections: `## Brief`, `## Tasks` (each with a `Verify:` done condition), and `## Review fixes`. The `brief` skill carries this format, so writing a Small plan needs no extra command. `plans/` is created on first use and is committed with the work. *Alternative:* OpenSpec with `skip_specs: true` for small work. Rejected, because it still produces a proposal and tasks plus four long command files.

**Review fixes are tasks in the plan.** Appending the picked findings under `## Review fixes` and running Build again keeps `tasks.md` the full record of what was built. Applied to this change itself, that rule would have caught the archived change whose outputs were later rolled back.

**`ask` holds only `git push`.** Every other `ask` entry would still prompt in `bypassPermissions` and defeat the reason for switching it on. Rules: `Bash(git push)`, `Bash(git push *)`, `PowerShell(git push)`, `PowerShell(git push *)`. *Alternative:* the hook returns `"ask"`. Rejected, because the docs do not say that a hook `"ask"` prompts in `bypassPermissions`, while an explicit ask rule is documented to.

**The hook forces the plain push form instead of judging pushes.** `.claude/hooks/guard.ps1` blocks any command that contains `git` and `push` as words where `push` is not directly after `git`, for example `git -C . push` or `git -c x=y push`. The message tells the agent to use `git push ...`, which the ask rule then catches. The hook never needs to know branch names, and the human still approves pushes to main when they ask for one. *Alternative:* block every push to `main` or `master` in the hook. Rejected, because the human wants the agent to push to main when told to.

**The hook blocks `.env` only as a path token.** A token matches when `.env` starts the token or follows `/`, `\`, a quote, `=`, or whitespace, and the next character is the end of the token, a quote, or one of `;`, `|`, `&`, `)`, `>`. Suffixes such as `.env.local` and `.env.example` match too, which keeps the hook consistent with the `Read(**/.env.*)` deny rule. `process.env.PORT` and `.venv` do not match. Blocking `.env.example` is accepted: the human can paste it when needed.

**Hook runtime.** The hook is `powershell.exe -NoProfile -ExecutionPolicy Bypass -File "${CLAUDE_PROJECT_DIR}/.claude/hooks/guard.ps1"` with matcher `Bash|PowerShell`, `timeout: 10`, and `onFailure: "block"`. It reads the event JSON from stdin, takes `tool_input.command`, and exits 2 with the reason on stderr to block, or 0 otherwise. Windows PowerShell 5.1 ships with every Windows machine, so the script stays compatible with 5.1 and needs no `pwsh`.

**Self-protection with deny, not ask.** Denying `Edit(.claude/settings.json)` and `Edit(.claude/hooks/**)` means future changes to those files are made by the human. `.claude/settings.local.json` stays editable, because `HARNESS-SETUP.md` step 3 has the agent create it.

**`enableAllProjectMcpServers: false`.** A project `.mcp.json` arrives through git, so a cloned repository could otherwise add MCP servers without the human seeing them.

**The old archive is marked, not rewritten.** A short `SUPERSEDED.md` in `2026-10-09-complete-engineering-workflow/` says that its outputs were rolled back and points to this change. Archived files stay as they were. When this change is archived, the human picks "Sync now", so that `openspec/specs/` finally holds the behavior that is actually live.

## Risks / Trade-offs

- [Each shell command starts `powershell.exe`, about 0.2–0.5 s] → Accepted for a guardrail that holds in bypass mode. A hook written in Node would also need a runtime on every machine.
- [The hook regex blocks a legitimate command] → The block message names the rule. The human runs the command themselves with `!`.
- [It is undocumented whether hooks run in `bypassPermissions` mode] → `README.md` "Check it works" adds a manual check in a bypass session.
- [Scripts can still read `.env`] → Stated in the README security section as a limit of native Windows without a sandbox.
- [Hard limit on `main`] → Only GitHub branch protection enforces it. The README and the final step of `HARNESS-SETUP.md` ask the human to turn it on.
