# Design

## Context

The harness is a template: `.claude/`, `AGENTS.md`, and `HARNESS-SETUP.md` are copied into a target repository (always a git repository) and set up there by an agent. Workflow rules reach agents through three channels: `AGENTS.md` (loaded every session), `openspec/config.yaml` (passed to agents only by `/opsx:propose` and `/opsx:apply`), and skills or subagents (loaded on demand). The `/opsx:*` command files are generated by OpenSpec and are regenerated by `openspec update`, so they cannot carry harness rules. A local skill library at `D:/General/Agent-Skill/skills/` holds vetted copies of third-party skills; `mattpocock/domain-modeling` and `mattpocock/grill-with-docs` are the sources for this change.

## Goals / Non-Goals

**Goals:**
- Every phase transition in the specs is stated where the agent sees it at that moment.
- No new always-loaded cost beyond the `domain-modeling` description and the added `AGENTS.md` lines.
- Third-party skills stay byte-identical to the library copy, so updating them is a plain copy.

**Non-Goals:**
- Enforcing phase gates with hooks.
- Changing how OpenSpec commands work.

## Decisions

**Phase transitions live in `AGENTS.md`.** "Name `/clear` then `/opsx:apply`", "run `plan-reviewer` after propose", "name `/review-change` after Build", "name `/retro` then `/clear` after archive", and the bug path apply in every session and at moments no single skill owns, so they go into the Human-Gated Workflow and Choosing-the-path sections. Alternative: a router skill; rejected because a user-invoked router cannot fire on its own and a model-invoked one costs a description every session anyway. `AGENTS.md` must stay under about 45 lines.

**`plan-reviewer` is a new subagent, not a mode of `verifier`.** It reviews planning artifacts before code exists and ends with `Ready to approve:`; `verifier` reviews a finished change and ends with `Ready to archive:`. One purpose per definition keeps each prompt short. Same tools as `verifier` (Read, Grep, Glob) so it cannot edit.

**`/review-change` is a user-invoked skill that orchestrates.** It follows the mattpocock pattern: a user-invoked skill may call model-invoked skills and subagents. It runs `verifier` through the Agent tool, `/code-review` and `ponytail-review` through the Skill tool, then merges findings. The name avoids the bundled `/verify` skill. Alternative: run reviews automatically at the end of Build; rejected because the human starts every phase.

**`/code-review` may be unavailable.** On a machine where `code-review` is set to user-invocable only, the Skill call is blocked. The skill then reports that axis as not checked and continues; it does not ask the human to type the command mid-run. Removing the personal override is a manual step outside this change.

**Vendored skills are copied unmodified.** `domain-modeling` (with `ADR-FORMAT.md` and `GLOSSARY-FORMAT.md`) and `grill-with-docs` are copied as-is, minus `agents/openai.yaml` (Codex metadata). ADR creation stays gated by the skill's own three conditions.

**`Verify:` is written by setup, not shipped in the template.** The template `AGENTS.md` has no `Verify:` line; `HARNESS-SETUP.md` step 4 adds one directly under the opening paragraph after the human confirms the command. `plan-reviewer` reads that line when present.

**The size rule lives in `rules.tasks`.** It applies exactly when tasks are written, at no cost to other sessions. The rule text avoids `": "`, which makes YAML read an item as a mapping and makes OpenSpec drop every tasks rule.

No new dependency is added.

## Risks / Trade-offs

- [`plan-reviewer` reports false positives] → its findings are advisory; the human approves or rejects the plan.
- [`/code-review` runs as a fork and inherits the Build session's context] → cost is roughly one session read, mostly cached, once per change.
- [More `AGENTS.md` lines dilute adherence] → each added line is a phase transition with no other home; the Reporting section shrinks to compensate.
- [Orca workers do not get these skills] → out of scope; `orca-delegate` already requires the worker to stop when plan and reality disagree.
